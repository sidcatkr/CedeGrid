# Live execution work log

## Connected execution path

`agent::run` maintains authenticated coordinator heartbeats, Prepared authorization, serial lease renewal, pending launch slots, local policy, result/checkpoint publication and reconciliation. Each allocation has an independent `__assignment-supervisor`. A supervisor persists Prepared only after identity, backend membership and required controls are verified; it persists Authorized before sending EXEC. Linux pidfd acquisition precedes any reaping. The fallback only signals the supervisor's unreaped direct child, never a rediscovered numeric PID.

Coordinator disconnection does not grant new authority. Relayed grants carry an absolute local monotonic expiry after subtracting RPC elapsed time. Agent EOF requests opportunistic drain; guaranteed work continues under its existing contract. A dead supervisor cannot enforce anything. Its uncertain reservations remain charged until read-only identity and GPU-release reconciliation succeeds. Linux terminated zombies are distinguished from live identities during reconciliation; no reconciliation path signals them.

Checkpoint/model downloads run as bounded pending preparations, counted against worker limits while the agent continues renewing existing allocations. Publications run independently from the control loop. Named input artifacts are verified before any supervisor spawn and exposed as `context.inputs` entries with name, local path, SHA-256 and size. Workers receive no coordinator credentials.

## Explicit managed-family contract

The original `single_process=true` contract still means the command cannot create child processes. `no_escape=true`, `single_process=false`, and `managed_child_limit=1..8` explicitly opt into supervisor-mediated child creation through the Python SDK. The bound is a lifetime limit for this allocation, including released child records; submit another bounded task to create a subsequent family. Each mediated child must itself declare single-process/no-escape and cannot create nested children. Uninstrumented forks, daemonization and escaping descendants remain unsupported.

The private Unix socket accepts versioned, bounded requests from the verified leader. Linux checks peer PID and UID plus the private token; macOS uses same-UID peer credentials and the private token and therefore reports the weaker trusted-client boundary. The API accepts commands and opaque request/child IDs, never a PID to adopt or signal. Duplicate request IDs return the existing child; changed commands with a reused ID are refused.

Every child has a durable Reserved/Prepared/Authorized/Running/release history and its own verified owned process handle. Children share the parent allocation's resource reservation. CPU/RAM/GPU observations are summed before one `max(requested, observed)` charge; pending/unknown child observation makes the aggregate unknown. Parent release is transactionally forbidden while any child remains reserved or uncertain. Parent exit drains the whole family; normal termination clocks start together, and error cleanup signals all owned children before waiting for release. GPU context release is polled per child without blocking another child's deadline. Arbitrary descendants are not inferred from a leader pidfd.

## Bounds and durability

Agent-created state, spool, logs, caches and temporary files stay below HOME, including a canonical check of the nearest existing state ancestor before creation. Backup archives and interrupted restore directories are refused as live state. Unsupported filesystems remain rejected; no mergerfs exception or underlying mount path was added.

`AgentConfig.cpu_affinity` optionally selects exact Linux CPU IDs. The current-thread agent, independent supervisor and each gate apply/read back the configured subset. CPU observations use matching allowed-CPU scopes. The verified `cpu.affinity` evidence is placement, not a CPU bandwidth guarantee. macOS refuses this explicit Linux control before user execution.

`max_transfer_bytes_per_second` defaults to 10 MiB/s across an agent, with 90% reserved for artifact traffic and 10% for control. Accounting includes JSON/hex expansion and conservative protocol overhead; transfers use 128 KiB raw chunks and a bounded initial burst. This is application pacing, not kernel network shaping.

Published model inputs use a node-local SHA cache and read-only hardlinks into private attempts. Cache bytes are verified before reuse. Spool accounting counts an inode once on Unix rather than repeatedly charging hardlinks. Cache eviction only removes unreferenced cache files; it never removes active input links or checkpoint/result storage. Following confirmed release, a durable final acceptance receipt, no active publication and no unresolved children, the agent can unlink accepted blobs, downloaded resume copies and input links while retaining descriptors, receipts, logs and journal history. Coordinator durable storage retains published bytes. Application-specific unpacked model copies remain the adapter's responsibility.

Managed stdout/stderr each retain at most 4 MiB while independent readers continue draining excess bytes. Each mediated child has separate bounded logs. No workload output is mixed with launch identity or agent control messages.

GPU execution requires complete NVML compute/graphics process APIs, one explicitly admitted GPU UUID and verified context absence after process exit. GPU memory budgets remain admission policies, never hard partitions or a zero-interference promise. Managed memory subtraction uses anonymous PSS on Linux; other platforms subtract a conservative zero lower bound without claiming zero actual use.
